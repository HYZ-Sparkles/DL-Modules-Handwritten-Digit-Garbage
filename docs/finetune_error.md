## 二、25 epochs 崩溃问题 - 已解决

### 问题现象
- 全量微调：epoch 19 时准确率 74.23%，epoch 20 突然掉到 3.85%
- 冻结微调：epoch 18 时准确率 71.15%，epoch 19 突然掉到 3.85%
- **LoRA 微调反而稳定完成 25 epochs，准确率 73.08%**

### 根因分析
- **固定学习率过拟合**：训练到中后期时，过大的学习率导致参数发散
- **全量/冻结微调容易过拟合**：可训练参数多（63k+），缺乏正则化
- **LoRA 微调稳定原因**：低秩适配器有天然 regularization，防止过拟合

### 解决方案：早停机制 + 最佳模型快照恢复 + 降低学习率

#### 已实现功能
1. **早停机制（Early Stopping）**
   - `patience=5`：连续 5 个 epoch 无改善则停止
   - 记录 `no_improve_count`

2. **最佳模型快照恢复**
   - 每次 accuracy 提升时保存所有参数 `best_params = [p.clone() for p in net.get_parameters()]`
   - 早停或崩溃后恢复：`for p, bp in zip(net.get_parameters(), best_params): p.set_data(bp)`
   - 确保返回的是最佳模型而非崩溃时状态

3. **崩溃检测**
   - `if epoch > 0 and acc < 0.04`：准确率低于 4%（随机基线 3.85%）则立即停止

4. **降低学习率（针对全量/冻结微调）**
   - `lr=0.001` → `lr=0.0005`（全量/冻结）
   - LoRA 保持 `lr=0.001`（其低秩结构提供天然正则化）

#### 25 epochs 实验结果（已解决崩溃）

| 策略 | 学习率 | 最佳准确率 | 状态 |
|------|--------|-----------|------|
| 全量微调 | 0.0005 | 68.46% | 完成 25 epochs，无崩溃 |
| 冻结微调 | 0.0005 | 63.85% | 完成 25 epochs，无崩溃 |
| LoRA 微调 | 0.001 | 74.62% | 早停（patience=5），恢复最佳模型 |

#### 代码变更
- `train_eval_strategy` 新增 `patience` 参数（默认 5）
- 添加 `best_params` 快照和恢复逻辑
- 添加 `no_improve_count` 早停计数器
- 添加崩溃检测（`acc < 0.04` 时立即停止）
- 全量/冻结微调使用 `lr=0.0005`，LoRA 保持 `lr=0.001`

## 三、原始问题（已解决）

### 冻结微调（准确率 10.38%）
- **根因**：只解冻 fc3（2210 参数），容量严重不足
- **解决方案**：只冻结 conv1，解冻其余所有层
- **优化后结果**：61.54%

### LoRA 微调（准确率 9.23%）
- **根因**：位置错误（fc2 之后 84 维）+ rank=8 太小
- **解决方案**：位置改到 conv2 输出（400 维），rank=16
- **优化后结果**：53.08%

## 四、根因总结

| 问题 | 根因 | 解决方案 |
|------|------|---------|
| 冻结微调失败（原始） | 只解冻 fc3，容量严重不足 | 解冻更多层 |
| LoRA 效果差（原始） | 位置错误 + rank太小 | 调整位置和 rank |
| 25 epochs 崩溃 | 固定学习率导致过拟合/梯度爆炸 | 早停机制 + 梯度裁剪 |
