# 模型改进任务问题分析

## 一、当前状态

### 基准
- **基准模型**：finetune_rubbish.py 全量微调
- **基准准确率**：71.15%
- **基准超参数**：lr=0.0005, epochs=25, batch_size=32, patience=5, Adam

### 硬性要求
- **不允许改变超参数**
- **不允许添加数据增强**
- **唯一变量：模型结构**

---

## 二、已尝试实验及结果

### 无效的改进策略
| 策略 | 模型结构 | lr=0.0005 结果 | 与基准差异 |
|------|----------|----------------|------------|
| 策略 A | BatchNorm（卷积层后） | 58.85% | -12.30% |
| 策略 B | 扩展分类头 | 68.85% | -2.30% |
| 策略 C | 双分类头取平均 | 65.77% | -5.38% |
| 策略 D | 更深 backbone（conv3） | 56.54% | -14.61% |
| 原始 LeNet5(ReLU) | 标准结构 | ~70.77% | -0.38% |
| LeakyReLU | LeNet5 + LeakyReLU | ~70.77% | -0.38% |
| ELU | LeNet5 + ELU | ~72.31% | +1.16% |
| 宽度增加 | conv1 6→8, conv2 16→20 | 5.00% | -66.15% |
| Dropout(p=0.8) | fc1后添加Dropout | 31.92% | -39.23% |
| Dropout(p=0.9) | fc1后添加Dropout | 2.31% | -68.84% |
| ELU+Dropout | 组合 | 34.23% | -36.92% |
| LeakyReLU+Dropout | 组合 | 18.85% | -52.30% |

### 成功策略（偶尔）
- **ELU**：在某些运行中达到72.31%，超越基准
- 但结果不稳定，有时只能达到70.38%

### 问题分析

#### 策略 A（BatchNorm）失败原因
- BatchNorm 改变了梯度分布，与预训练权重不兼容
- 收敛速度变慢，需要更多 epochs 才能发挥效果

#### 策略 B（扩展分类头）失败原因
- 新增层随机初始化，训练开始阶段大量参数需要从零学习
- 拖累整体收敛速度

#### 策略 D（更深 backbone）失败原因
- 结构变化（新增 conv3）导致预训练权重无法加载到 fc1/fc2
- 随机初始化的全连接层严重拖曳性能

#### 宽度增加失败原因
- 所有卷积层和全连接层结构全部变化
- 预训练权重几乎全部无法加载
- 训练完全崩溃

#### Dropout 失败原因
- Dropout 改变了梯度传播路径，与预训练权重不兼容
- p=0.9 时训练直接崩溃
- p=0.8 时训练缓慢，最终崩溃

#### 组合策略失败原因
- Dropout 的破坏性影响远超其他改进
- 所有带 Dropout 的组合都导致训练崩溃

---

## 三、核心发现

### 预训练权重兼容性是关键
1. **任何结构变化都可能破坏预训练权重加载**
2. **Dropout 与预训练权重完全不兼容**
3. **宽度增加导致所有层结构变化，完全无法加载**

### 唯一成功的改进
- **ELU 激活函数**：在某些运行中超越基准71.15%
- 但结果不稳定，波动较大

### 待解决问题
- 如何在保持预训练权重兼容性的同时提升模型性能？
- 如何让 ELU 的改进效果更稳定？
